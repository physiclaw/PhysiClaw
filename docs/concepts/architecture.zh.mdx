## 硬件

PhysiClaw 的硬件采用 [CoreXY](https://corexy.com/) 运动结构：两个步进电机驱动触控笔在 X/Y 平面上移动，电磁铁驱动触控笔沿 Z 轴运动，完成点击。控制板运行 [FluidNC](https://github.com/bdring/FluidNC) 固件，通过 USB 串口接收电脑上的服务器发来的 [G-code](https://zh.wikipedia.org/wiki/G代码) 指令，并转换为触控笔的移动和点击。

## MCP 工具

PhysiClaw 将底层硬件操作封装为一组 MCP 工具，供智能体直接调用：通过摄像头查看手机屏幕、获取截图、执行常用手势、把文本复制到手机剪贴板等。

| 分组 | 工具 |
| --- | --- |
| 观察 | `peek`、`screenshot` |
| 手势 | `tap`、`double_tap`、`long_press`、`swipe` |
| 导航 | `home_screen`、`go_back`、`force_quit` |
| 解锁 | `unlock_phone` |
| 文本 | `send_to_clipboard` |
| 连续动作 | `sequence` |

### OCR 与图标检测

PhysiClaw 对摄像头画面和截图做 OCR 和图标检测，再把结果连同压缩后的图片提供给智能体。

### 坐标映射

图像像素坐标 → 手机屏幕坐标 → 物理平面坐标，整条链路需要两个变换矩阵来换算。

运行前需要有效的校准数据，以获得准确的变换矩阵。硬件位置未变时，可以复用已有校准数据；移动硬件后需要重新校准。

### 截图

摄像头画面不够清晰时，机械臂点击一次辅助触控按钮，触发快捷指令截屏，并将截图直接上传到服务器，全程无需切换页面。

### 输入文字

对人来说，用手机键盘打字很容易；智能体却需要逐键定位和点击。手机按键小而密集，难以点准，而且每按一个键都要调用一次大模型，既慢又容易出错，还浪费 token。

更好的做法是通过快捷指令从电脑获取文本，写入剪贴板后直接粘贴，既快又准确。

快捷指令是 iOS 独有功能，安卓没有原生替代方案，因此 PhysiClaw 目前使用 iPhone。

## 运行时循环

运行时会持续检查两件事：是否有定时任务到期，以及手机屏幕是否因新通知而亮起。满足任一条件，就唤醒智能体。

唤醒后，智能体解锁手机，读取微信消息，打开对应 App 完成任务，把结果反馈给用户，最后保存日志并结束会话。

## 上下文管理

智能体完成一项任务通常需要多次调用大模型，每次都附带一张手机屏幕图片。没有合适的上下文管理，很快就会达到上下文窗口上限。

**压缩上下文。** 每次调用大模型时，模型除了返回要执行的操作，还会返回一段简短描述。系统只保留最近一轮的原始图片，并将更早轮次的图片替换为 OCR 文本；随着轮次增加，再把这些文本压缩为每步一句话的摘要。

**更新进度。** 提示词会要求大模型在关键步骤记录任务进展。进度信息保留在消息列表末尾，帮助模型在上下文压缩后继续完成当前任务。

**让缓存稳定命中。** 把系统提示词、工具描述、记忆等固定内容放在最前面，并保持逐字节一致。压缩上下文时尽量少改动前面的内容，因为每处改动都会使缓存从改动处失效。

## Conductor

Conductor 负责运行 [playbook](/zh/custom/playbooks/)。用户的任务与某个可用的 playbook 匹配时，由 Conductor 直接执行，不再让智能体逐步操作。Playbook 内置 App 的先验知识，大部分步骤可程序化执行，因此模型调用更少，token 成本更低。
