# Hardware document sources

This directory owns the assembly manual, sourcing guide and extrusion drawings.
It is separate from the authored website pages in the repository's root `docs/`.
The website serves generated hardware documents from published release assets.

| What to edit | Source |
| --- | --- |
| Required parts, quantities, specifications and applications | `bom/bom.json` |
| Suppliers, reference prices and ordering instructions | `sourcing/vendors/cn.json` or `sourcing/vendors/global.json` |
| Optional tools and their suppliers | `sourcing/optional_tools.json` |
| Assembly instructions and chapter layout | `manual/content/*.json` |
| Manual appearance | `assets/manual/styles.css` |
| Sourcing appearance | `assets/sourcing/styles.css` |
| Sourcing checklist and copy interactions | `assets/sourcing/checklist.js` (inlined into HTML) |
| Manual page structure and required fields | `manual/schema.py` |
| Extrusion parts and BOM validation | `drawing/extrusion_parts.py` |
| Extrusion drawing presentation | `drawing/extrusion.py` |
| Engineering dimensions and profiles | `../assembly/travel_ranges.py` and `../parts/standard/extrusion_spec.py` |
| Document date | `MANUAL_VERSION`, updated at the user's discretion |

`bom/bom.json` is the authored purchasing list. Each row has a stable `part_id`;
vendor files join to these identifiers. Markets (`cn` and `global`) are separate
from languages; the current Chinese and English editions use them respectively.
The purchasing list is separate from the CAD-derived per-step BOMs generated by
`hardware.assembly.bom`.

`bom/loader.py` reads and validates the list for all three documents. Its package
initializer contains only a docstring; consumers import the loader explicitly.

The manual's `content/11_bom.json` owns chapter headings and table presentation.
Its table page uses `"rows_source": "bom"` to load the shared purchasing rows.
Keep the rows in `bom/bom.json`, rather than copying them into a chapter or
supplier file. Sourcing and drawings read the shared list without loading manual
chapters or importing another document's builder.

From the repository root:

```sh
make hw-manual
make hw-manual-pdf
make hw-sourcing
make hw-sourcing ARGS=--scaffold
make hw-url
make hw-drawing
make hw-check
uv run --locked --group cad pytest tests/hardware tests/test_architecture.py
```

Document builders and static checks use only the Python standard library.
`make hw-drawing` generates HTML and PDFs by default.
The manual requires existing assembly SVGs; PDF builds require a Chromium-family
browser. Generated files remain in `hardware/output/{manual,sourcing,drawing}`
or the output tree selected by `PHYSICLAW_HW_OUTPUT`. Release preparation builds
fresh documents in its private tree, using the validated persistent CAD cache.

Direct Python entry points are `hardware.documents.manual.build`,
`hardware.documents.sourcing.build`, and `hardware.documents.drawing.extrusion`.

The manual loader validates page layouts and required fields before rendering.
Errors name the chapter, page ID and field; `make hw-check` runs the same
validation. Add new page types to both `manual/schema.py` and `manual/build.py`.
Inline HTML and styles remain authored content, and empty translations still
fall back to English.

The manual builder's `--browser` option accepts `chrome` (default, Chrome/Chromium)
or `edge` (Windows only). macOS and Linux use Chrome/Chromium. The selection
applies only when `--pdf` is requested; a missing or unsupported selected browser
fails before existing manual outputs are cleared.

```sh
uv run --locked python -m hardware.documents.manual.build --pdf --browser chrome
```

## Travel-dependent content

Set `X_TRAVEL` and `Y_TRAVEL` in
[assembly/travel_ranges.py](../assembly/travel_ranges.py) and update the matching
[runtime constants](../../src/physiclaw/core/hardware/arm.py) to the same values.
Hardware generators use the hardware copy; architecture tests check that both
copies agree.

Keep travel-dependent lengths and quantities as named tokens in the BOM, manual
chapters and vendor files, for example `"{X_RAIL_LENGTH} mm"`.
[dimensions.py](dimensions.py) defines and resolves these tokens, including those
inside supplier part codes and copyable inquiries. Undefined dimension tokens
fail validation.

Manual assembly and exploded-view illustrations use the original 110 × 200 mm
travel proportions. Tables and technical drawings state the configured
dimensions and quantities. The default output locations are:

| Output | Purpose |
| --- | --- |
| `hardware/output/step/` | Manufacturing STEP files used in release downloads |
| `hardware/output/svg/` | Assembly SVGs; used by the manual at 110 × 200 mm travel |
| `hardware/output/manual-illustrations/` | Reference SVGs, intermediate STEP files and a separate CAD cache for custom travel |

`PHYSICLAW_HW_OUTPUT` changes the output root for all of these paths. A full
`make hw-build` generates the required illustrations; the manual build fails if
any are missing. `make hw-step` builds only the requested step. Release preparation
uses the same full build and reuses the validated caches.

## Manual supplier URL review

`make hw-url` shows up to three Taobao/Tmall and three AliExpress links, including
notes and optional tools. All shown links are recorded as checked before interaction.
In a terminal, any key opens the next browser tab; `q` or Esc quits.
Piped output only lists links.

Each pool picks URLs shown the fewest times in the rolling last 30 days.
Age, BOM order and vendor order rank ties, with slight randomness.

History: `hardware/output/.url-checks.json` (follows `PHYSICLAW_HW_OUTPUT`).
Use `ARGS=--verbose` for full specs or `ARGS="--state /path/to/history.json"`.
