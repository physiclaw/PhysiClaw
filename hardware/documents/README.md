# Hardware document sources

This directory owns the assembly manual, sourcing guide and extrusion drawings.
It is separate from the authored website pages in the repository's root `docs/`.
The website serves generated hardware documents from published release assets.

| What to edit | Source |
| --- | --- |
| Required parts, quantities, specifications and applications | `bom/bom.json` |
| Suppliers, reference prices and ordering instructions | `sourcing/vendors/cn.json` or `sourcing/vendors/global.json` |
| Optional tools and their suppliers | `sourcing/optional_tools.json` |
| Assembly instructions and chapter layout | `manual/content/*.json` |
| Manual or sourcing appearance | The respective `styles.css` |
| Extrusion drawing presentation | `drawing/extrusion.py` |
| Engineering dimensions and profiles | `../assembly/travel_ranges.py` and `../parts/standard/extrusion_spec.py` |
| Document date | `MANUAL_VERSION`, updated at the user's discretion |

`bom/bom.json` is the authored purchasing list. Each row has a stable `part_id`;
vendor files join to these identifiers. Markets (`cn` and `global`) are separate
from languages; the current Chinese and English editions use them respectively.
The purchasing list is separate from the CAD-derived per-step BOMs generated by
`hardware.assembly.bom`.

`bom/loader.py` reads and validates the list for all three documents. Its package
initializer contains only a docstring; consumers import the loader explicitly.

The manual's `content/11_bom.json` owns chapter headings and table presentation.
Its table page uses `"rows_source": "bom"` to load the shared purchasing rows.
Keep the rows in `bom/bom.json`, rather than copying them into a chapter or
supplier file. Sourcing and drawings read the shared list without loading manual
chapters or importing another document's builder.

From the repository root:

```sh
make hw-manual
make hw-manual-pdf
make hw-sourcing
make hw-sourcing ARGS=--scaffold
make hw-drawing
make hw-check
uv run --locked --group cad pytest tests/hardware
```

Document builders and static checks use only the Python standard library.
The manual requires existing assembly SVGs; PDF builds require a Chromium-family
browser. Generated files remain in `hardware/output/{manual,sourcing,drawing}`
or the output tree selected by `PHYSICLAW_HW_OUTPUT`. Release preparation builds
fresh documents in its private tree, using the validated persistent CAD cache.

Direct Python entry points are `hardware.documents.manual.build`,
`hardware.documents.sourcing.build`, and `hardware.documents.drawing.extrusion`.
